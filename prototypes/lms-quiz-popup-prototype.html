In-Video Question Checkpoint

Every Drawing Room lesson video contains a point where the narrator stops and asks the learner a question. Today the question is painted into the video and the learner just watches it go by. This page specifies the replacement: a popup the LMS draws over the player at that exact second, which the learner actually answers before the video continues.

What happens, in order

This is a sequence, so the numbering is real — each step waits on the one before it.

  1. Playback reaches the checkpoint. The LMS watches currentTime and fires at the second we give you. The video pauses itself — the learner should not have to pause it.
  2. The popup opens over the paused frame. The frame stays visible and dimmed behind it, so the learner keeps the context they were just taught.
  3. The learner picks one of four options. One click. No submit button, no confirmation step.
  4. The system says right or wrong, immediately. Correct: the option turns green and the video may continue. Wrong: their choice turns terracotta, the correct option is revealed in green, and the explanation appears.
  5. The learner continues. One button closes the popup and resumes playback from the same second. A wrong answer does not block them and is not scored — this is a comprehension check, not a test.

What we would send you per video

One array of checkpoints alongside the video. We generate this from the script, so it arrives with the video and needs no manual authoring on your side. The example below is the real checkpoint from Autonomy 01 — The Autonomy Spectrum.

quiz checkpoint payload · json
{
  "videoId": "autonomy-01-spectrum",
  "checkpoints": [
    {
      "id":          "q1",
      "atSeconds":   42,          // fire here; pause playback
      "preamble":    "Let's answer a quick question, to check the concept landed.",
      "stem":        "Which could the helper safely run alone?",
      "options": [
        "Read an order back",
        "Give a cash refund",
        "Wire money from the till",
        "Approve a supplier invoice"
      ],
      "correctIndex": 0,
      "explanation":  "Reading an order back is easy to undo: if the helper gets it wrong, Ali fixes it in seconds. The other three move money, and once money has moved nobody can pull it back in time."
    }
  ]
}

Behaviour rules

The parts that are easy to get subtly wrong, stated so nobody has to guess.

SituationRequired behaviour
Reaching atSecondsPause playback and open the popup automatically. Never wait for the learner to notice a button.
Correct answerOption turns green with a tick. Verdict reads “That's right.” The explanation still shows — the learner who guessed deserves the reasoning too.
Wrong answerTheir option turns terracotta with a cross, and the correct option turns green. Then the same explanation. Both must be visible at once, so they can see what they mixed up.
Answering twiceNot possible. All four options are disabled the moment one is chosen — no changing the answer after seeing the result.
Trying to skipThe popup has no close button and no click-outside-to-dismiss. The only exit is Continue the video, which appears only after answering.
Seeking past itIf a learner drags the timeline past an unanswered checkpoint, the checkpoint should still fire. Otherwise the check is trivially skippable.
RewatchingFire again. A rewatch is usually a learner who wants another go at understanding it.
Keyboard & screen readersOptions reachable by Tab and answerable with 1–4; focus moves into the popup on open and to Continue after answering; the verdict is announced via aria-live.
Mobile / narrow playerThe popup scales with the player, never overflows it, and options stay a comfortable tap size.

Decisions for you

Four things the demo assumes. Overrule any of them — they are cheap to change now and awkward later.

Does a wrong answer get recorded?

The demo records nothing. If you want completion or comprehension reporting, we need to know what to send and where. assumed: not stored

One explanation, or one per option?

The demo shows a single shared explanation for any wrong answer. Per-option feedback teaches better but triples the authoring. assumed: one shared

Where does the checkpoint list come from?

We can hand it over as JSON beside the video file, or expose an endpoint you call by videoId. Your call — whichever fits your ingestion. assumed: JSON alongside

One question per video, or several?

The payload is an array, so several works. Today every video has exactly one, placed about two-thirds through. assumed: one, extensible
