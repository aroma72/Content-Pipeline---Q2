In-Video Question
Checkpoint

Every Drawing Room lesson video contains a point where the narrator stops and asks the learner a question. Today that question is painted into the video, so nobody can answer it. This document specifies the replacement: a popup the LMS draws over the player at an exact second, which the learner must answer before the video continues.

In-Video Question CheckpointThe four states

The four states

Everything the component has to render. All four captured from the working demo.

1 · playing

Before the checkpoint. Ordinary playback. The only hint is the marker on the timeline, which is optional — the learner does not need to know it is coming.

2 · question

At 0:39 the video pauses itself and the popup opens over the dimmed frame. Four options, no submit button, no close button.

3 · correct

Right answer. The chosen option turns green with a tick. The explanation still shows — a learner who guessed deserves the reasoning too.

4 · wrong

Wrong answer. Their choice turns terracotta with a cross and the correct option turns green, both visible at once, so they can see exactly what they mixed up.

In-Video Question CheckpointFlow and data

What happens, in order

  1. Playback reaches the checkpoint. The player watches currentTime and fires at the second we supply. The video pauses itself — the learner should not have to pause it.
  2. The popup opens over the paused frame. The frame stays visible and dimmed behind it, so the learner keeps the context they were just taught.
  3. The learner picks one of four options. One click. No submit step, no confirmation.
  4. Right or wrong, immediately. Correct: green tick. Wrong: their choice in terracotta, the correct answer revealed in green, then the explanation.
  5. The learner continues. One button closes the popup and resumes from the same second. A wrong answer does not block them and is not scored — this is a comprehension check, not a test.

What we would send you per video

One array alongside the video. We generate it from the script, so it arrives with the video and needs no authoring on your side.

quiz checkpoint payload · json
{
  "videoId": "autonomy-01-spectrum",
  "checkpoints": [
    {
      "id":           "q1",
      "atSeconds":    39,        // fire here; pause playback
      "preamble":     "Let's answer a quick question, to check the concept landed.",
      "stem":         "Which could the helper safely run alone?",
      "options": [
        "Read an order back",
        "Give a cash refund",
        "Wire money from the till",
        "Approve a supplier invoice"
      ],
      "correctIndex": 0,
      "explanation":  "Reading an order back is easy to undo: if the helper gets it wrong, Ali fixes it in seconds. The other three move money, and once money has moved nobody can pull it back in time."
    }
  ]
}

In-Video Question CheckpointRules and decisions

Behaviour rules

SituationRequired behaviour
Reaching atSecondsPause playback and open the popup automatically. Never wait for the learner to notice a button.
Answering twiceNot possible. All four options are disabled the moment one is chosen.
Trying to skipNo close button, no click-outside-to-dismiss, no Escape. The only exit is Continue the video, which appears only after answering.
Seeking past itIf a learner drags the timeline past an unanswered checkpoint, it should still fire — otherwise the check is trivially skippable.
RewatchingFire again. A rewatch is usually someone who wants another go at understanding it.
Keyboard & screen readersOptions reachable by Tab and answerable with keys 1–4; focus moves into the popup on open and to Continue after answering; the verdict is announced via aria-live.
Narrow player / mobileThe popup scales with the player and never overflows it. Sizes in the demo are set in container units for exactly this reason.
Where the checkpoint sitsPlace it on a scene beat, not on one of our full-screen text cards, so the popup has a clean ground behind it.

Decisions for you

Four assumptions the demo makes. Overrule any of them — cheap now, awkward later.

Does a wrong answer get recorded?

The demo records nothing. If you want completion or comprehension reporting, tell us what to send and where. assumed: not stored

One explanation, or one per option?

A single shared explanation for any wrong answer. Per-option feedback teaches better but triples the authoring. assumed: one shared

How does the payload reach you?

JSON beside the video file, or an endpoint you call by videoId — whichever fits your ingestion. assumed: JSON alongside

One question per video, or several?

The payload is an array, so several works. Today every video has exactly one, about two-thirds through. assumed: one, extensible
