# Systems Evaluations — Video 1: What is Systems Evaluation?
**Course**: Agentic AI | **Topic**: Systems Evaluations  
**Video**: 1 of 4  
**Target Duration**: ~12 minutes  
**Objective**: Learners understand what evaluation is, why it matters, and how it differs from testing.

**Narration**: "You just built an AI agent. It looks good. Your code passes all tests. But here's the question: Is it actually good? I don't mean, does it compile. I mean, does it do what you actually want it to do? That's what systems evaluation answers. And it's way more important than most people think."

**Animation**: Title card appears with smooth fade-in: "Systems Evaluation: Quality Control for AI Agents"

## Scene 1.2: The Problem

**Visual**: Split screen showing Left: Green checkmarks and "TESTS PASSING" text appearing, Right: Confused user face expressing frustration. Use professional UI elements.

**Narration**: "Let me tell you a real story. A company built a customer support chatbot. All their unit tests passed. Performance was great. They deployed it. Two weeks later, users are complaining: The bot is rude. It makes up information. It tells customers things that are completely wrong. How did this happen? The tests passed! Here's the thing: Tests check if your code works. But they don't check if your agent actually solves the problem it's supposed to solve. That's where evaluation comes in."

**Animation**: Transition between split screens. Show the gap between "tests pass" and "real world fails" with a visual disconnect (e.g., arrow pointing from left to right, then breaking).

## Scene 1.3: Testing vs Evaluation

**Visual**: Animated diagram showing side-by-side comparison. Left side shows testing (code, checkmarks, technical details). Right side shows evaluation (user outcomes, quality metrics, feedback).

**Narration**: "Let's be crystal clear about the difference. Testing asks: Does the code run? Does it break? If I give it input X, do I get output Y? Testing is important. You definitely need it. But it's narrow. It's focused on the code. Evaluation asks a different question: Does the agent achieve its goal? Does the output actually help users? Is it high quality? Think of it this way. Testing is like checking: Does the machine work? Does it turn on? Does it stop when I turn it off? Evaluation is like asking: Does the product that comes out of the machine actually work for customers? Can they use it? Do they like it? Both matter. But they're measuring different things."

**Animation**: Animated comparison table appears with smooth slide-in effect:
- Aspect: Testing | Evaluation
- Asks: Does code work? | Does agent achieve goals?
- Measures: Code execution | Output quality
- Scope: Individual functions | End-to-end behavior
- When: During development | Continuous

**Narration** (continued): "Here's the key insight: A test can pass, but evaluation can fail. And that means you have a problem."

## Scene 1.4: Real Example

**Visual**: Screen share showing a glossary output on screen. Use real example from Systems Evaluations learner pack. Point to specific glossary entries. Annotate with red circles for errors, yellow for vague definitions.

**Narration**: "Let me show you a real example. This is a glossary that was generated by an AI agent. Let's evaluate it. First, a test might ask: Did the agent return a glossary? Yes. Test passes. But now let's evaluate it. Is it complete? Well, the session talked about 10 concepts, but the glossary only has 5. So, incomplete. Is it accurate? Let me check... Some definitions are vague. One is actually wrong. Is it clear? Some definitions use jargon that learners don't understand. So the test passed. But the evaluation says: This glossary is low quality."

**Animation**: Glossary appears on screen. Checkmarks appear for test checks. Then red X's appear for evaluation failures. Annotations highlight issues (incomplete, inaccurate, unclear).

**Narration** (continued): "That's the difference. Tests say yes or no. Evaluation says: How good is this? Where does it fail? How can we improve it?"

---

## Scene 1.5: Why Evaluation Matters

**Visual**: B-roll montage of production systems, dashboards showing real-time monitoring, users interacting with AI systems, data analytics visualizations.

**Narration**: "Here's why you care about this: When you ship an agent, you're responsible for what it does. If your agent gives wrong information, harms users, or produces garbage, that's on you. Evaluation is how you catch these problems before they reach users. Evaluation is how you know: Is my agent ready to ship? What should I improve? Am I making progress? When do I regress? Without evaluation, you're flying blind. With evaluation, you have data. You can say: 'Last week, pass rate was 90%. Today it's 88%. Something broke. Let me investigate.' Without evaluation, you don't know until users complain."

**Animation**: Show production incident timeline. Metrics dashboard appears with trend lines. Highlight the moment a regression is detected vs the moment a user complains. Show time gap between detection and complaint.

---

## Scene 1.6: The MEASURE Framework

**Visual**: Animated diagram showing the MEASURE loop. Each letter appears one at a time with icons and brief descriptions. Use circular flow to show continuous iteration.

**Narration**: "Evaluation isn't a one-time thing. It's a continuous loop. We call it the MEASURE loop. M — Measure what matters. Pick 3-5 metrics that tell you if your agent is working. E — Explore failures. When something goes wrong, collect the data and understand what happened. A — Assess root causes. Why did it fail? Was it the prompt? The data? The tool? S — Sum up health. Compile your findings. 'Agent pass rate is 92%.' U — Unblock improvements. Based on what you learned, what do you fix? And then you loop back to M. Measure again. See if you improved. This loop runs forever. Measure, improve, measure, improve. That's how you build and maintain high-quality agents."

**Animation**: MEASURE loop animates with smooth transitions. Each letter builds on the previous. Show arrows flowing clockwise showing the continuous nature. Include simple icons for each step (ruler for Measure, magnifying glass for Explore, etc.).

**Outro Narration**: "In the next video, we're diving deeper into the MEASURE framework. You're going to see exactly how this works with real code. For now, remember this: Evaluation is not testing. Evaluation is continuous. And it's essential."
