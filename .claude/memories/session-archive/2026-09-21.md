### Known weaknesses in what was built 2026-09-21 — act on these

Written down because they are not visible from the code and all four tests pass anyway.

1. **DNS rebinding is NOT closed.** `verify-url.js` calls `dns.lookup` to prove a host is public,
   then `fetch()` resolves the name a SECOND time. A low-TTL attacker-controlled domain can answer
   public on the check and private on the fetch. `server/lib/webhook.js` has the same TOCTOU, so this
   is house-consistent rather than a new hole — but the references path is reachable by prompt
   injection (a hostile search result persuades the model to propose the URL), which the webhook path
   is not. Closing it needs a custom agent that pins the checked IP for the connection.
2. **Links are verified once, at build time, and never again.** The LMS stores and renders them
   indefinitely. Link rot will make a verified list wrong within months. Nothing re-checks.
3. **`WEB_SEARCH_USD_PER_REQUEST = 0.01` is a hardcoded literal** in `llm.js` with no test pinning
   it — the same drift shape as the blockedBy set that had gone 6/7/9 ways. It should live in
   `prices.js`.
4. **`wantReferences` is fixed when a course is built.** There is no way to add references to a
   lesson that already exists; it would need a requeue and a full rebuild.
