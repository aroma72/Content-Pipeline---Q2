EXERCISE · MEMORY ARCHITECTURE

memory.md

Build your project's journal — a running record of what you learn as you work.

What you're making

memory.md is your agent's journal. Unlike the handbook (rules that rarely change), the journal is where you write what you learn as you go — one short, honest note per work session. It's how a lesson survives, so neither you nor your agent repeats the same mistake next week.

Your task

Ask Claude Code to create the file for you — don't write it all by hand.
💬 Where do you do this? In the Claude Code chat. Claude Code is the AI assistant that works right inside your project, and its chat box — the text box where you type — is where you talk to it. So: open your project in Claude Code, click into the chat box at the bottom, type or paste the instruction below, and press Enter to send it. Claude replies in that same chat and creates the file for you. Every step of this exercise happens in that chat.
Send a message like this:
"Create a memory.md journal for this project. Add 5 dated entries from our recent work sessions — each with a date, the task, and one true lesson I learned."
Then read the file Claude made and tally it against the checklist below. Your job is to review and verify — not to write it all yourself.

Read & tally — does Claude's file include…

  • ☐ 5+ entries, each with a clear date
  • ☐ the real task each entry refers to
  • ☐ one true lesson per entry — a real decision, mistake, or insight (not generic filler)

If an entry looks vague or invented, send it back: "Entry 3 is too generic — replace it with a real lesson from our actual work." Repeat until the tally passes.

💡 Hint — how to do it

Refresher — what "good" looks like (your yardstick when reviewing Claude's file)

The format is deliberately simple. A short, true note beats a long, polished one. Each entry should answer: "What did I learn that I don't want to lose?" Use the example below to judge whether Claude's entries are real and specific.

Example
# memory.md

2026-06-18 · weekly report
Tried sending the report as a big table — too cluttered.
Next time → use short bullet points.

2026-06-19 · onboarding email
A long intro paragraph got ignored.
A one-line summary at the top worked far better.
Tip: your first few entries may feel awkward or too simple — that's completely normal. Keep going; the entries add up fast.

📤 Final step — push it to GitHub

Once Claude has created your file, commit and push it to your existing project's GitHub repository — the same project you've been working in this week, not a new repo. From your project folder:

git add memory.md
git commit -m "Add memory.md journal"
git push
✅ Done when: memory.md (created by Claude Code, reviewed and tallied by you) has 5+ dated entries that pass your checklist — and it's pushed to GitHub.
