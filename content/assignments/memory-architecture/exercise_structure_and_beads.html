structure.md  +  Beads

Organize your project so things have a home — and track your work so nothing slips.

What you're making

Two habits that work together: a structure.md that says where everything lives, and a Beads task tracker that follows each task's whole life. A tidy project gives your information a home; the tracker gives your work a memory.

Your task

PART 1 — Organize (structure.md)
Sort your project files into clear folders (e.g. notes/, instructions/, data/). Add a structure.md that explains where each kind of thing lives. Then test it — ask your agent to find one file and confirm it goes straight there.
PART 2 — Track (Beads)
Set up Beads by giving the link below to your Claude and asking it to set up Beads as instructed there:
https://github.com/gastownhall/beads
For example, paste this to Claude: “Set up Beads in my project, following the instructions here: https://github.com/gastownhall/beads” — and let it do the setup for you.

Once it's set up, run the whole system end-to-end to see whether it actually works — create a task, open it, move it through its states (in progress → blocked/waiting → done), and close it. The point is to watch the tracker work, not to hit a task quota.
⚠️ Remember: Beads is not just a to-do list — it's a task tracker. A to-do list only shows what's left; a tracker follows the whole life of each task (opened → in progress → blocked/waiting → done).

💡 Hint — how to do it

Refresher + Example — structure.md

One short file that maps your folders. Keep it to a line per folder.

# structure.md
notes/         → my notes & journal (memory.md lives here)
instructions/  → rules for the agent (CLAUDE.md)
data/          → raw data & exports
decisions/     → decision.md
Refresher + Example — Beads tracker

Each task is an item you open and close; the status shows where it stands.

.beads — task tracker
☑ Write the script            done
▶ Render the video            in progress
⌛ Get reviewer approval       waiting on review
☐ Add captions                to do
Tip: after you build it, ask your agent to "find the data" — watch it go straight to data/. That's a well-organized project.

📤 Final step — push it to GitHub

Once both are set up, commit and push them to your existing project's GitHub repository — the same project you've been working in this week, not a new repo. From your project folder:

git add structure.md .beads
git commit -m "Add structure.md and Beads tracker"
git push
✅ Done when: structure.md exists (plus one example of your agent finding a file) and you've run Beads end-to-end — a task moving through its states and closing — confirming the whole tracker works — and both are pushed to GitHub.
